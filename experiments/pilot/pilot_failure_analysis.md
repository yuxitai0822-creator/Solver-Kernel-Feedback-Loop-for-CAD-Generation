## F-003 — *UPDATE 2026-07-16 20:00* — root cause found (now B-004)

| | |
|---|---|
| **Symptom** | All 4 methods × 18 samples × all iterations showed `pipeline_valid=False` per `iter_records[*]`. Spot-checking any `iter_00/adapter_report.json` reveals `step_export_status: "pass"` (literal `"pass"`, lowercase). |
| **Bug** | `run_benchmark_v0.2.py::_pipeline_valid()` compares `adapt_report.get("step_export_status") == "success"`. The adaptor uses the LITERAL `pass` for step_export (and `success` for adapter_status), creating an enum mismatch. **Every** step_export comparison returns False, even when the STEP file actually exported successfully. |
| **Consequence** | The pilot's Success@3=0 across all methods is a **false negative**: the IR was successfully rendered to STEP, but the validator rejected it because of the string typo. The 72-run pilot actually has real Success@3 numbers hidden by this bug. |
| **Action** | Filed as **B-004** in `experiments/bugs/bug_db.json`. The single-line fix `accept {"success", "pass"}` (and similar) inside `_pipeline_valid()` is the proposed resolution. Estimated 15 min. Once B-004 is fixed, the pilot outcomes can be re-read without re-running. |
| **Status** | **critical — needs decision** before any further pilot/batch invocation. |
