# KQP v0.1 Instances (Samples 1-3 templates)

This directory contains **hand-written** KQP instance JSON files for sample
templates demonstrating the v0.1 schema. Three samples cover the three main
profile types in the 50-design-plan set:

| Sample | Profile | KQP file |
|---|---|---|
| 100243_9fb796fe_0005 | rectangle (1.9×1.9×20 cm) | `100243_9fb796fe_0005.kqp_instance.json` |
| 102314_91648bfc_0000 | annulus (12.7/7.97 × 101.6) | `102314_91648bfc_0000.kqp_instance.json` |
| 103552_c3a389ed_0003 | stadium+2holes (200/12.5/6.5) | `103552_c3a389ed_0003.kqp_instance.json` |

These 3 templates establish the query-emission pattern for compiler_v0.1 to
follow. The remaining 47 instances will be generated by the KQP compiler
in `kqp_compiler/`.

## Query patterns by profile type

### rectangle / rectangular_frame
```json
{"intent": "body_count", "expected": 1, "source_field": "$.target.body_count"}
{"intent": "bbox_size", "axis": "u", "expected": L, "source_field": "$.solid_bodies[0].dimensions.profiles[0].length_u.value"}
{"intent": "bbox_size", "axis": "v", "expected": W, "source_field": "$.solid_bodies[0].dimensions.profiles[0].width_v.value"}
{"intent": "bbox_size", "axis": "w", "expected": H, "source_field": "$.solid_bodies[0].dimensions.extrude_distance.value"}
{"intent": "is_solid", "expected": true, "source_field": "(implicit)"}
{"intent": "occt_valid", "expected": true, "source_field": "(implicit)"}
```
Plus `through_void_count` only if inner rings exist.

### annulus
Same as rectangle, plus:
```json
{"intent": "cylinder_radius", "expected": R_outer, "source_field": "$.solid_bodies[0].dimensions.profiles[0].outer_radius.value"}
{"intent": "cylinder_radius", "expected": R_inner, "source_field": "$.solid_bodies[0].dimensions.profiles[0].inner_radius.value"}
```
And `through_void_count: 1` always.

### stadium (+ optional inner rings for holes)
Same as rectangle, plus:
```json
{"intent": "bbox_size", "axis": "u", "expected": straight + 2*r, "source_field": "...straight_length+radius"}
{"intent": "bbox_size", "axis": "v", "expected": 2*r, "source_field": "...radius"}
```
If inner rings exist, `through_void_count: N`.

### circle (sample 30, 39, 40, 50)
```json
{"intent": "bbox_size", "axis": "u", "expected": 2*r, "source_field": "$.solid_bodies[0].dimensions.profiles[0].radius.value"}
{"intent": "bbox_size", "axis": "v", "expected": 2*r, ...}
{"intent": "cylinder_radius", "expected": r, "source_field": "...radius.value"}
```

### rectangle + flipped frame (samples 18, 19, 48/49)
Same as rectangle — flip does not affect query values.

### arbitrary_closed (sample 37)
Profile-specific — **TODO**: define arbitrary_closed query patterns. Currently
the schema supports `bbox_size` for the extrude axis, but the in-plane dims

## What is NOT in these 3 templates (intentionally)

- **No `face_count`/`edge_count`/`vertex_count`/`shell_count`/`wire_count`** —
  these are GT-only topology fields; v0.1 schema marks them as
  "open_extension_points" but compiler will NOT emit them (Non-Leakage).
- **No `volume` / `plane_area`** — design_plan_v0.6 has no area/volume fields;
  compiler will not emit these queries.
- **No `center_distance` between two centers** — schema has the intent but no
  explicit design_plan field for the *second* center's coords; requires
  design_plan v0.7 extension.
- **No `hole_radius` query** — would query OCCT directly; design_plan tracks
  hole radii inside `dimensions.profiles[*].hole_radii` but compiler version
  may not surface all such structures yet. v0.2.
